# Handoff Notes

## Project Overview

Self-hosted home media server stack running on Docker Compose on Fedora 44. The repo lives at `~/home-server` and the active Docker runtime lives at `~/docker`.

---

## Repo Structure

```
~/home-server/
├── docker-compose.yml          # main compose file, includes active services
├── master-compose.yml          # symlink/copy used by Docker at ~/docker/master-compose.yml
├── compose/                    # individual service compose files (75+)
├── configs/                    # seed configs for services (homepage, qbittorrent, etc.)
├── scripts/
│   ├── udms.sh                 # first-time setup script
│   ├── functions.sh            # all setup functions, sourced by udms.sh
│   ├── config.env              # shell-only config (TZ, SERVER_IP, DATADIR, script paths)
│   ├── bash_aliases            # docker aliases added to shell on setup
│   └── bash_aliases.env.example
├── .env.example                # documents all Docker environment variables (reference only)
└── assets/                     # service icons
```

## Runtime Structure

```
~/docker/
├── .env                        # actual Docker env vars, never committed, generated by udms.sh
├── master-compose.yml          # copy of repo's docker-compose.yml
├── compose/                    # copy of active compose files
├── appdata/                    # all service config/data volumes
├── secrets/                    # secret files (plex_claim etc.)
├── shared/config/              # bash aliases and env for shell
└── logs/
```

---

## Config/Env System

- `scripts/config.env` — committed, shell script use only. Has TZ, SERVER_IP, DATADIR, and script internal paths. Never read by Docker Compose.
- `.env.example` — committed, Docker variable reference/template only. No secrets, no script internals.
- `~/docker/.env` — never committed, generated by `udms.sh` on first run. Uses `.env.example` as base template, appends dynamic values (PUID, PGID, homepage URLs) and secrets entered at prompts.
- Secrets (API keys etc.) live only in `~/docker/.env`.

## Current Work — TorBox Media Center Debugging

### What it does
Generates `.strm` files from the user's TorBox cloud library and organizes them into `movies/` and `series/` folders. Jellyfin reads these as streaming pointers — no local storage needed.

### Problem
The official `anonymoussystems/torbox-media-center:latest` image uses TorBox's search API for metadata classification (movies vs TV shows), but that API has been restricted for third-party use. As a result everything gets dumped into `movies/` regardless of whether it's a TV show.

### Current Fix
Building from a community PR branch that replaces the API-based metadata lookup with local filename parsing using the PTN library:

- PR: https://github.com/TorBox-App/torbox-media-center/pull/68
- Branch: https://github.com/DanCorley/torbox-media-center/tree/remove-metadata-search-api

The compose file builds directly from the PR branch:

```yaml
build:
  context: https://github.com/DanCorley/torbox-media-center.git#remove-metadata-search-api
  dockerfile: dockerfile
```

### Current Status
- Container is running and generating `.strm` files at `$DATADIR/media/torbox-strm/`
- `ENABLE_METADATA=true` is set so PTN-based classification is active
- Some files with non-standard naming (e.g. `101 Cardinal`, `102 Delorme`) are still landing in movies/ because their filenames don't have `S01E01` style patterns
- Jellyfin libraries should point to:
  - Movies: `/data/media/torbox-strm/movies`
  - Series: `/data/media/torbox-strm/series`

### Decypharr
Decypharr is also running with a FUSE mount of the TorBox library at `/data/media/torbox`. It requires `privileged: true` due to FUSE restrictions on Fedora with SELinux. This is separate from torbox-media-center — Decypharr handles downloads/symlinks for Sonarr/Radarr, torbox-media-center handles the browse/stream library for Jellyfin.
